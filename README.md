# 월간 커리어 · 뉴스레터 스튜디오

대학 경력개발·취업지원 담당자가 월별 프로그램을 모아 뉴스레터를 만들고, 지난달 자료와 상시 프로그램을 재사용하는 로컬 웹 프로그램입니다. 토토구구의 블루·네이비·민트, 곡선 그래픽과 넓은 여백을 적용했습니다. 공식 대학 CI나 실제 대학의 서비스로 표시하지 않습니다.

## 설치와 실행

Node.js 22.12 이상 또는 호환되는 최신 LTS와 npm이 필요합니다. 이 프로젝트는 Node.js 24 환경에서 검증했습니다. 별도 API 키·환경 변수·백엔드·회원가입은 없습니다.

```powershell
cd 'C:\국민대 프로젝트\newsletter'
npm install
npm run dev
```

브라우저에서 **http://localhost:5173/#/newsletters** 를 여세요. 포트는 5173으로 고정되어 있습니다. 이미 사용 중이면 오류를 표시하고 종료합니다. 다른 포트로 자동 변경하지 않습니다. 사용 중인 동일 프로젝트 서버가 있다면 그 주소를 사용하세요. 종료는 실행 터미널에서 `Ctrl+C`입니다. 실행 중인 다른 프로그램의 프로세스를 임의로 종료하지 마세요.

```powershell
npm run typecheck
npm run test
npm run test:e2e
npm run build
```

E2E는 Windows에 설치된 Microsoft Edge를 사용합니다. Edge가 없다면 Playwright의 브라우저를 설치하고 `playwright.config.ts`의 `channel`을 환경에 맞게 변경해야 합니다. 최초 npm 설치에는 인터넷이 필요합니다. 설치 이후 편집·저장·출력은 외부 서비스에 접속하지 않습니다. 개발 서버를 실행한 상태에서 사용하세요. `file://`로 편집 앱을 실행하는 방식은 지원하지 않습니다.

## 바로 체험하기

1. **샘플 살펴보기**: 가상의 미래대학교 프로그램 12개, 6개 카테고리, 상시·추천·마감 상태, 로컬 그래픽을 임시 미리보기로 봅니다. 이 단계에서는 사용자 뉴스레터 DB를 변경하지 않습니다.
2. **샘플로 시작**을 선택하면 지정한 월에 저장합니다. 동일 월은 중복 생성할 수 없습니다.
3. 빈 문서로 시작하려면 **새 뉴스레터**를 누르고 월을 선택한 뒤 생성합니다.
4. 카테고리 입력창에 `진로 탐색 워크숍`을 입력하고 Enter를 누르세요. 항목을 클릭하면 상세를 편집할 수 있습니다.
5. **지금 저장** 또는 `Ctrl+S`로 즉시 저장합니다. 일반 입력은 800ms 후 자동 저장되고, 계속 입력하면 최대 5초마다 저장합니다.

예제 입력:

| 필드 | 예제 |
|---|---|
| 프로그램명 | 나의 다음 걸음 · 커리어 워크숍 |
| 대상 | 재학생 및 졸업생 |
| 주요내용 | 관심 직무를 알아보고 나만의 경험을 정리해요. |
| 신청기간 유형 | 기간 지정 |
| 신청 종료일 | 2026-11-17 |
| 신청 URL | https://example.com |

기준일을 2026-11-10으로 바꾸면 종료일 11-17은 D-7, 11-13은 D-3, 11-10은 오늘마감, 11-09는 모집종료로 표시됩니다. 샘플은 체험 시점의 서울 날짜를 기준으로 날짜를 계산하며 실제 정책·일정이 아닙니다.

## 월별 반복과 상시 프로그램

- **복제**에서 다음 달을 선택합니다. 일반 프로그램의 기존 날짜는 이동하지 않습니다. ‘일정 확인 필요’가 표시되므로 상세에서 확인 완료하세요.
- 활성 상시 원본은 새 월에 한 번만 복사됩니다. 원본 수정은 기존 월을 바꾸지 않습니다. 자동 불러오기 OFF인 원본은 포함하지 않습니다.
- 편집 화면의 **상시 불러오기**는 직접 선택한 원본만 병합합니다. 기존 항목은 중복 생성하지 않고, 삭제된 항목을 선택하면 최신 원본으로 복구합니다.
- 프로그램/카테고리 드래그 또는 **위로·아래로**를 사용하세요. 카테고리 간 이동은 상세의 선택 메뉴로도 가능합니다.
- 삭제 알림의 **실행취소**는 8초 동안 제공합니다. 알림 위에 마우스나 키보드 포커스가 있으면 남은 시간이 멈춥니다. 연속 삭제도 개별 복구할 수 있습니다.

## 저장과 데이터 보호

핵심 자료는 IndexedDB의 `career-newsletter` 데이터베이스에 저장됩니다. 한 브라우저·한 사용자 환경입니다. 같은 `http://localhost:5173` 주소와 같은 브라우저 프로필을 계속 사용하세요. `127.0.0.1`, 다른 포트, 다른 브라우저 프로필은 별도 저장소입니다.

브라우저 데이터 삭제나 시크릿 모드 종료로 자료가 사라질 수 있습니다. **설정·백업 → 전체 백업 다운로드**로 정기적으로 ZIP을 보관하세요. 공용 PC에는 입력 자료가 남으므로 개인정보나 비밀키를 입력하지 마세요. 앱 자체 암호화·로그인은 없습니다.

입력 오류가 있으면 원문을 화면과 복구 초안에 보관하고 마지막 정상값을 저장합니다. 오류 해결 전에는 출력이 차단됩니다. 저장 실패는 성공으로 표시하지 않으며 상단에 재시도와 초안 다운로드를 제공합니다. Web Locks 지원 브라우저에서는 같은 월을 연 두 번째 탭은 읽기 전용입니다. 저장 직전 revision 검사도 적용합니다. 충돌 시 최신 자료를 조용히 덮어쓰지 않습니다.

삭제 자료는 soft delete하며 같은 세션에서 파일을 정리하지 않습니다. 다음 실행 시 7일이 지난 삭제 자료와 참조 없는 오래된 파일만 정리합니다. 다른 월이나 원본이 참조하는 파일은 유지합니다.

## 파일과 공개 범위

- 이미지: JPEG/PNG/WebP, 10MB 이하, 25메가픽셀 이하. 원본과 긴 변 1600px 이하 썸네일을 저장합니다. SVG/GIF/HEIC 업로드는 지원하지 않습니다.
- 첨부: PDF/DOCX/XLSX/PPTX/TXT/CSV, 20MB 이하. 각각 최대 5개를 연결할 수 있습니다.
- 일반 첨부는 **독자 공개 포함 OFF**가 기본입니다. 이미지는 ON이 기본입니다.
- 연결 해제는 해당 항목의 참조만 제거합니다. 다른 월에 연결된 원본 파일은 바뀌지 않습니다.
- 원격 URL은 신청 링크로만 사용하며 이미지를 자동 수집하지 않습니다.

## 내보내기

미리보기와 HTML·이미지·인쇄는 같은 `NewsletterDocument`와 표시 필터를 사용합니다. 수동 숨김·숨긴 카테고리·삭제·종료 자동 숨김을 동일하게 적용하고 선택한 기준일로 고정합니다. 처리 시작 시 저장 후 스냅샷을 생성합니다.

- **웹 뉴스레터 (.html)**: CSS, 이미지와 공개 첨부를 단일 파일에 포함합니다. 앱을 종료해도 파일을 직접 열 수 있습니다. 한글과 모바일 레이아웃을 지원하며 외부 폰트·사용자 스크립트가 없습니다. 30MB 초과는 확인, 50MB 초과는 차단합니다. 공개 첨부 링크가 브라우저에서 열리지 않으면 파일 다운로드로 저장하세요.
- **PNG/JPG**: 800px 또는 1600px. 긴 문서는 최대 높이 8000px 이내로 먼저 DOM을 분할하고 여러 이미지를 ZIP으로 다운로드합니다. 너무 긴 단일 카드는 내부에서 나눕니다. 링크는 클릭되지 않으며 첨부는 파일명과 원문 안내로 표시합니다.
- **PDF로 저장**: 브라우저 인쇄창을 열고 사용자가 ‘PDF로 저장’을 선택합니다. A4 세로·12mm 여백, 텍스트 및 링크를 유지하는 HTML 인쇄 방식입니다. 인쇄 대화상자의 머리글·바닥글과 배경 그래픽 설정에 따라 결과가 달라집니다. 첨부 바이너리는 넣지 않습니다.

기본 파일명은 `career-newsletter-YYYY-MM.*`이며 이미지 ZIP 안의 파일명은 `career-newsletter-YYYY-MM-part-01.png` 형식입니다. PDF 파일명은 브라우저 인쇄창에서 지정할 수 있습니다.

## 전체 백업과 복원

백업 ZIP에는 `manifest.json`, `data.json`, `assets/{UUID}/original`과 선택 썸네일이 들어갑니다. **내부 보관용이므로 비공개 첨부도 포함합니다.** 복구 초안·실행취소 큐·삭제 자료는 일반 백업에서 제외합니다.

가져오기는 전체 교체입니다. ZIP의 버전·스키마·관계·순서·허용 MIME·파일 크기·SHA-256·안전한 경로를 먼저 검증하고 요약을 보여줍니다. 현재 자료 백업 및 ‘기존 데이터 전체 교체’ 확인 후 하나의 IndexedDB 트랜잭션으로 교체합니다. 손상 파일이나 실패는 기존 DB를 유지합니다. 200MB 입력, 500MB 해제 총량, 5000개 파일 한도를 적용합니다.

## 검증과 지원 범위

실제로 실행한 결과와 미확인 사항은 [검증 기록](./VALIDATION.md)을 참고하세요. Windows Edge를 자동 검증 기준으로 사용했습니다. Chrome 계열의 최신 브라우저를 권장하지만 설치된 브라우저 외의 버전별 실기기 검증을 완료한 것으로 간주하지 않습니다.

후속 범위인 설치형 PWA/개발 서버 종료 후 오프라인 재실행, 인쇄창 없는 직접 PDF 다운로드, 일괄 작업, 서버·협업·이메일 발송은 제공하지 않습니다. 앱 편집은 localhost 개발 서버 실행이 필요하고, 내보낸 HTML은 독립 실행됩니다.

## 구현 구조와 디자인 결정

- React + TypeScript + Vite SPA, HashRouter, Zustand 초안, Dexie 트랜잭션, Zod 검증, fflate ZIP, html-to-image 캡처.
- 화면 코드는 목록/편집/상시/설정, 도메인/저장소/파일/출력/백업/독자 문서로 분리했습니다. 소규모 프로젝트이므로 요구사항 예시의 모든 하위 디렉터리는 만들지 않았습니다.
- 정렬은 브라우저 드래그를 사용하며 위로·아래로·카테고리 이동을 동등하게 제공합니다. 별도 드래그 패키지는 추가하지 않았습니다.
- 날짜는 서울 날짜 문자열과 달력 정수 차이로 처리합니다. 날짜 유틸을 위해 별도 라이브러리를 추가하지 않았습니다.
- 시스템 한국어 글꼴을 사용해 외부 폰트 요청을 없앴습니다. 토토구구 토큰은 `src/tokens.css`, 반응형 UI는 `src/style.css`, 독자 화면·출력은 `src/document.css`에 있습니다.
- 테마는 기본 레이아웃을 공유하고 색·문구·곡선의 각도·모양을 바꿉니다. 장식은 내용과 겹치지 않으며 모션 감소를 존중합니다.
- CSP는 `index.html`에 적용합니다. 정적 서버로 배포한다면 같은 정책을 HTTP `Content-Security-Policy` 헤더로도 전달하고 개발용 WebSocket 허용을 제거하세요. 외부 서버 공개는 이 작업의 범위에 포함하지 않았습니다.

기술 구현 확인에 사용한 1차 자료: [React 공식 문서](https://react.dev/learn), [Vite 공식 가이드](https://vite.dev/guide/), [Dexie 트랜잭션 문서](https://dexie.org/docs/Transaction/Transaction). 실제 의존성 버전은 설치 시 npm registry에서 확인해 `package-lock.json`에 고정했습니다.
